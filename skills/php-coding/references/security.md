# Security

Read when: a diff builds SQL, writes a value into HTML, hashes or checks a password, makes a token or compares a secret, calls `unserialize()`, `exec()`, `shell_exec()`, `system()`, `passthru()`, or `proc_open()`, opens or includes a path built from input, parses XML, touches session setup or form handling, or fetches a URL taken from input.

Deterministic backstop: `composer audit --locked` in CI. It checks the locked packages against security advisories and exits non-zero when one matches ([CLI](https://getcomposer.org/doc/03-cli.md#audit)). Since Composer 2.9, `update`, `require`, and `remove` also refuse a version with a known advisory, but `install` from a lock file does not, so keep the CI audit ([changelog](https://getcomposer.org/changelog/2.9.0-RC1), [config](https://getcomposer.org/doc/06-config.md#policy)).

Nothing else here is deterministic. PHPStan level 8 checks types, not where a value came from, and has no taint analysis ([rule levels](https://phpstan.org/user-guide/rule-levels)). A green build can ship every rule below broken.

## Rules

- **SQL values go through bound parameters.** Use `PDO::prepare()` with `?` or `:name` placeholders and pass the values to `execute()`. A placeholder stands for a whole value, so write `LIKE ?` and bind `"%{$term}%"`, never `'%?%'` ([prepared statements](https://www.php.net/manual/en/pdo.prepared-statements.php)). Do not build the string with `PDO::quote()` or an escape function; the manual recommends `prepare()` instead and OWASP marks escaping "STRONGLY DISCOURAGED" ([PDO::quote](https://www.php.net/manual/en/pdo.quote.php), [SQL injection](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)).
- **Identifiers and sort direction cannot be bound, so map them from an allowlist.** For table names, column names, and `ASC`/`DESC`, OWASP says "input validation or query redesign is the most appropriate defense" ([SQL injection](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)). Put the value from your array into the SQL, never the input.

  ```php
  $column = ['name' => 'u.name', 'created' => 'u.created_at'][$sort] ?? 'u.name';
  $direction = $descending ? 'DESC' : 'ASC';
  $stmt = $pdo->prepare("SELECT u.id, u.name FROM users u WHERE u.team_id = ? ORDER BY {$column} {$direction}");
  $stmt->execute([$teamId]);
  ```

- **Escape HTML at output with `htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')`.** Those flags are the default since PHP 8.1 (before that it was `ENT_COMPAT`, which leaves single quotes raw). Do not narrow them to `ENT_COMPAT` or `ENT_NOQUOTES`, and do not use `ENT_IGNORE`, which the manual says "may have security implications". Pass the charset, because an omitted one comes from `default_charset` ([htmlspecialchars](https://www.php.net/manual/en/function.htmlspecialchars.php)).
- **The output context decides the encoder.** Quote every attribute value. A value inside a URL is `rawurlencode()`d first, then HTML-escaped ([rawurlencode](https://www.php.net/manual/en/function.rawurlencode.php)). `htmlspecialchars()` translates only `& " ' < >`, so a whole URL taken from input needs its scheme checked (`https` or `http`) before it goes into `href` or `src`. Do not put input directly inside `<script>`, `<style>`, an HTML comment, or an `on*` handler; OWASP calls these dangerous contexts where encoding does not prevent XSS ([XSS prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)).
- **Passwords use `password_hash()`, `password_verify()`, and `password_needs_rehash()`.** Hash with `PASSWORD_DEFAULT` (bcrypt, default cost raised from 10 to 12 in PHP 8.4) or with `PASSWORD_ARGON2ID` when PHP is built with Argon2, which OWASP prefers; bcrypt truncates input at 72 bytes, so cap passwords there ([password_hash](https://www.php.net/manual/en/function.password-hash.php), [password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)). Store the hash in a column that can grow (the manual suggests 255 bytes), and after a successful `password_verify()` call `password_needs_rehash()` and save the new hash ([password_needs_rehash](https://www.php.net/manual/en/function.password-needs-rehash.php)). Never `md5()`, `sha1()`, or `hash('sha256', ...)`: they are "designed to be very fast" ([password FAQ](https://www.php.net/manual/en/faq.passwords.php)).
- **Tokens, keys, and nonces come from the CSPRNG.** Use `random_bytes()`, `random_int()`, or `new \Random\Randomizer()`, whose default engine is `Random\Engine\Secure` ([random_bytes](https://www.php.net/manual/en/function.random-bytes.php), [Randomizer](https://www.php.net/manual/en/random-randomizer.construct.php)). The manual says `rand()`, `mt_rand()`, `uniqid()`, and `lcg_value()` "must not be used for cryptographic purposes", and `lcg_value()` is deprecated as of PHP 8.4 ([mt_rand](https://www.php.net/manual/en/function.mt-rand.php), [uniqid](https://www.php.net/manual/en/function.uniqid.php), [lcg_value](https://www.php.net/manual/en/function.lcg-value.php)). Do not hand a `Random\Engine\Mt19937` to a Randomizer that makes secrets.
- **Compare secrets with `hash_equals($known, $userSupplied)`.** A `===` comparison takes longer the further the strings match, which leaks the secret; the user value goes second ([hash_equals](https://www.php.net/manual/en/function.hash-equals.php)). Never `==`: two numeric strings compare as numbers ([comparison](https://www.php.net/manual/en/language.operators.comparison.php), see `idioms.md`).
- **Mark secret parameters `#[\SensitiveParameter]` (PHP 8.2).** The value is then redacted from stack traces ([SensitiveParameter](https://www.php.net/manual/en/class.sensitiveparameter.php)). `password_hash()` and `hash_equals()` already carry it; your own functions that take a password, key, or token do not until you add it. Log redaction is in `monolog.md`.
- **`unserialize()` never sees untrusted input.** The manual says so "regardless of the options value of `allowed_classes`", because object instantiation and autoloading can run code ([unserialize](https://www.php.net/manual/en/function.unserialize.php), [deserialization](https://cheatsheetseries.owasp.org/cheatsheets/Deserialization_Cheat_Sheet.html)). Use `json_decode()`. For data you stored yourself, verify a `hash_hmac()` signature with `hash_equals()` first and still pass `allowed_classes`; leaving the option out allows every class.
- **Avoid the shell, and never interpolate input into a command string.** OWASP's first defense is a built-in function (`mkdir()`, not `system('mkdir ...')`); next is `proc_open()` with an array command (PHP 7.4), which runs without a shell and escapes each element ([OS command injection](https://cheatsheetseries.owasp.org/cheatsheets/OS_Command_Injection_Defense_Cheat_Sheet.html), [proc_open](https://www.php.net/manual/en/function.proc-open.php)). Symfony Process takes the same array form (see `symfony-components.md`). Otherwise wrap each input in `escapeshellarg()`, not `escapeshellcmd()`, before `exec()`, `shell_exec()`, `system()`, or `passthru()` ([escapeshellarg](https://www.php.net/manual/en/function.escapeshellarg.php)); the result is still one argument, and `--help` is an argument, so check the value cannot start with `-`.
- **A file path from input is replaced by a key, or resolved and checked.** Prefer a lookup (`$files[$id]`) or `basename()`, and allow only what you expect ([filesystem security](https://www.php.net/manual/en/security.filesystem.php)). Otherwise `realpath()` both sides and require the target to start with the base plus a separator ([OWASP Symfony sheet](https://cheatsheetseries.owasp.org/cheatsheets/Symfony_Cheat_Sheet.html)). `realpath()` strips the trailing slash and returns `false` for a missing file ([realpath](https://www.php.net/manual/en/function.realpath.php)), so a bare prefix test lets `/srv/uploads-old` pass, and a file you are about to create is checked through its directory.

  ```php
  $base = realpath('/srv/uploads');
  $path = realpath($base . '/' . $name);
  if ($base === false || $path === false || !str_starts_with($path, $base . DIRECTORY_SEPARATOR)) {
      throw new InvalidArgumentException('Path is outside the upload directory.');
  }
  ```

- **`include` and `require` never take a path built from input.** They evaluate the file as PHP ([include](https://www.php.net/manual/en/function.include.php)). Map the input to a fixed list of files, and keep `allow_url_include` off ([PHP configuration](https://cheatsheetseries.owasp.org/cheatsheets/PHP_Configuration_Cheat_Sheet.html)).
- **XML keeps PHP 8's defaults.** From PHP 8.0 external entities are not loaded by default, so `libxml_disable_entity_loader()` is deprecated; do not add it ([libxml_disable_entity_loader](https://www.php.net/manual/en/function.libxml-disable-entity-loader.php), [XXE](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html)). For untrusted XML do not pass `LIBXML_NOENT`, `LIBXML_DTDLOAD`, `LIBXML_DTDATTR`, `LIBXML_DTDVALID`, or `LIBXML_PARSEHUGE`; the manual flags each as enabling XXE or as trusted-data only ([libxml constants](https://www.php.net/manual/en/libxml.constants.php)). If you need entity substitution, add `LIBXML_NO_XXE` (PHP 8.4, libxml 2.13 or later).
- **Regenerate the session ID at login and at every privilege change.** Call `session_regenerate_id()` before writing the authenticated flag to `$_SESSION` ([session management](https://www.php.net/manual/en/features.session.security.management.php), [OWASP sessions](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)). OWASP shows `session_regenerate_id(true)`. The PHP manual warns that deleting the old session at once loses sessions under concurrent requests and asks for a short expiry timestamp on the old one instead ([session_regenerate_id](https://www.php.net/manual/en/function.session-regenerate-id.php)). Pick one on purpose.
- **Harden the session cookie.** Set `session.use_strict_mode=1`, `session.use_only_cookies=1`, `session.cookie_httponly=1`, `session.cookie_secure=1` on HTTPS, and `session.cookie_samesite` to `Lax` or `Strict`. Strict mode is off by default and the manual calls it "mandatory for secure sessions" ([session INI](https://www.php.net/manual/en/session.security.ini.php)). Set them in `php.ini`, or per request with the array form of `session_set_cookie_params()` (PHP 7.3) before `session_start()`; its `partitioned` key needs 8.5 ([session_set_cookie_params](https://www.php.net/manual/en/function.session-set-cookie-params.php)).
- **A state-changing request carries a CSRF token when the app renders its own forms.** Generate it with `random_bytes()`, store it in the session, send it in a hidden field or header (not a cookie, not the URL), and reject the request unless `hash_equals()` matches ([CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)). Do not change state on `GET`. OWASP treats `SameSite` as defense in depth, not a replacement for the token.
- **A URL from input is not fetched as given.** OWASP says not to accept a full URL: take a host or IP, match it against an allowlist, and build the request from a scheme, port, and path you fix ([SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)). Disable redirects so they cannot bypass the check. `file_get_contents()` over `http` follows them unless the stream context sets `follow_location` to `0` ([HTTP context](https://www.php.net/manual/en/context.http.php)); for Guzzle see `guzzle.md`.
